## Discovery gate

Each package must define an outcome, user value, primary workflow, data/consent boundary, feasibility or prototype evidence, threat model, compatibility constraints, failure/fallback behavior, acceptance, migration impact, rollback, and an approved decision record.

Discovery tasks use `D<package>-<number>` IDs. They do not receive `RQ-*` evidence requirements until the capability is implementation-ready.
